# 《打boss》α 切片范围（Scope Lock）

> **文档版本**：v1.0 ｜ 2026-10-14
> **效力**：这是**当前唯一在做的范围**。凡与本文冲突的"1.0 完整版"描述，一律以本文为准。
> **上游约束**：[`个人开发可行性.md`](./个人开发可行性.md) —— 现金 **¥2,000~3,000**、**无外部人力**、1 人 + AI
> **实现规格**：[`静态帧影像规格.md`](./静态帧影像规格.md)（画面怎么做）、[`对话与场景系统设计.md`](./对话与场景系统设计.md)（玩法怎么表达）
> **数据落点**：`data/shots.json`（镜头表，已含 `scope` 块）、`data/story/*.json`（剧本）

---

## 0. 一句话定义

**α 不是"完整游戏的 14%"，是一个能被陌生人独立玩懂的 14 分钟短篇。**

- 有完整开局 → 3 个事件 → 1 个结局，能从头玩到尾，**能发布**
- 全部资产（32 张分层图 / 9 张立绘 / 1 条视频）**100% 可被 1.0 复用**，不是一次性丢弃的演示
- 判据只有一条：**把它发到 itch.io，陌生人能不能玩完。**

> 反面定义：α ≠ "把 1.0 砍一半"。砍一半的 1.0 是一个没有结局的半成品，那种东西发不出去。

## 1. 硬范围（1.0 → α）

| 维度 | 1.0 完整版 | **α 切片** | 裁剪 |
|---|---:|---:|---:|
| 事件数 | 20 | **3** | 15% |
| 结局数 | 5 | **1** | 20% |
| 职级档位 | 8（rank 0~7） | **3**（rank 0~2） | 38% |
| NPC 数 | 5 | **4**（3 主 + 1 提及） | 80% |
| 场景数 | 22 | **3** | 14% |
| 成片时长 | 97 分钟 | **约 14 分钟** | 14% |
| 选择点数 | 约 40 | **3** | 7.5% |

**选择点数只有 3 个，这是刻意的。** 「分支-收束」结构下，每多一个选择点，抽卡与剪辑人力按事件数线性增长（见 [`减法组合预算.md`](./减法组合预算.md) 第五节）。alpha 的全部张力来自**信息差与立场**，不来自分支数量。

## 2. 场景清单（3 个）

场景 id 直接对应 `data/shots.json` 里的 `scenes` 键，镜头表已经建好，**不需要再设计机位**。

| # | 场景 | `scene_id` | 职能 | 已定义镜头 | 唯一分层图 |
|---|---|---|---|---:|---:|
| S1 | 三号会议室 | `meeting_room` | 规则被宣布的地方（压迫感） | 6 | 14 |
| S2 | 开放办公区 | `office_floor` | 日常与疲惫（主场） | 6 | 11 |
| S3 | 茶水间 | `pantry` | 非正式信息交换（人际） | 3 | 7 |
| | | | | **15** | **32** |

**预留（α 不做）**：`night_office` 深夜办公区（4 张）——留给 β 与 1.0 的结局段落。
它已经建在镜头表里，α 阶段**不生成任何图**，`docs/拍摄单.md` 会把它列在"预留"组。

**每个场景固定 3 个机位**，够讲完所有事件：

1. **定场全景**（`*_wide`）—— 进入场景时用，交代空间
2. **反打中景**（`*_left` / `*_right` / `*_over_*`）—— 对话主体，按说话人自动切换
3. **静物特写**（`*_detail_*`）—— 规则叙事的核心机位，承载信息不承载表演

> 静物特写是这条路线最漂亮的杠杆：无人物、不需表演、AI 可用率最高（约 50%），却承载最关键的信息。白板上的季度格是"轮回"的物理形态。

## 3. 事件清单（3 个）

全部从策划书第 8 章的 20 事件池里直接取用，**不新写设定**。

| # | 事件 | `id` | 场景 | 主要 NPC | 痛点 | 选择点 |
|---|---|---|---|---|---|---|
| E1 | 周报扩写运动 | `weekly_report_inflation` | S1 会议室 | 季衡 / 沈听澜 | 形式主义汇报 | 1（3 选项） |
| E2 | 成果署名之争 | `credit_dispute` | S2 办公区 | 唐破晓 | 功劳与规则 | 1（3 选项） |
| E3 | 茶水间版本流言 | `pantry_rumor_version` | S3 茶水间 | 梁叙 | 流言与信息 | 1（3 选项） |

**选这三个的理由**（不是随便挑的）：

- **一个场景一个事件**，资产零浪费，3 个事件正好把 3 个场景各用满一次
- **三种痛点互不重复**：形式主义 / 功劳分配 / 信息流言——各自对应一套不同的解题姿势，玩家能感到"这个游戏的规则是多样的"
- **四个 NPC 各带一种立场**：季衡（务实但有权力惯性）、沈听澜（要用证据说话）、唐破晓（同级竞争者）、梁叙（信息枢纽）
- **E1 已有完整剧本**（`data/story/evt_01_weekly_report.json`，35 节点 / 13 次切镜 / 13 句台词），E2、E3 照它的结构写即可

**每个事件的结构固定为**：

```
定场镜头 → NPC 抛出台词（2~3 句）→ 旁白点出两难 → ★选择（3 选项）
        → 三个收束分支各 2~3 句 → 结算飘字 → 滑向下一个时段
```

约 **35 节点 / 12~14 次切镜 / 350~450 字台词**。三个事件合计约 **1,100 字台词、105 个节点、40 次切镜**。

## 4. 结局（1 个）

**只做【清醒离场结局】路径 A（主动离职）**（策划书 §7.4）。

| 项 | 内容 |
|---|---|
| 触发条件 | 玩家在 E3 选择"离职"类选项，且 `health >= 20` |
| 为什么选它 | 它是**唯一在 rank 0~1 就能合理到达**的结局。其余四个都需要爬到 CEO 或走完整轮回机制——那是 β 以后的事 |
| 表现 | 静态帧 + 引擎动效（拉开镜头） + **1 条可灵数字人独白**（约 20 秒） |
| 时长 | 约 90 秒 |

**这一条视频是 α 唯一允许付钱生成的动态画面**，也是验证"视频层准入规则"是否跑得通的唯一机会。其余段落一律静态帧。

> 不做的四个结局：破局 / 沉沦 / 困局轮回 / 职场淘汰。它们的触发条件依赖完整晋升链与回溯机制，α 里没有。

## 5. 职级与数值（3 档）

| rank | 职级 | α 中的状态 |
|---|---|---|
| 0 | 实习生 | 开局 |
| 1 | 专员 | E1~E3 之间可能到达 |
| 2 | 高级专员 | α 内的天花板（不强制到达） |

七维数值（绩效 / 专业 / 影响力 / 声望 / 健康 / 精神负荷 / 资源）**全部保留**，规则一行不改——直接复用现有 `autoload/game_state.gd`。

α 只做一件事：让玩家在 **3 个选择点上看到七维的变化**。左栏常驻的 `StatBar` 是这条体验的地基（见 [`UI设计方案.md`](./UI设计方案.md)）。

## 6. 资产与费用（α 实际要花多少）

| 资产 | 数量 | 可用率 | 需生成 | 单价 | 小计 |
|---|---:|---:|---:|---|---:|
| 场景分层图 | 32 张 | 35% | 约 92 张 | ¥0.20/张 | **¥18** |
| 立绘（4 角色 × 2~3 表情） | 9 张 | 35% | 约 26 张 | ¥0.20/张 | **¥5** |
| 结局视频 | 20 秒 | 40% | 50 秒 | ¥0.80/秒 | **¥40** |
| TTS 配音（约 1,100 字） | — | — | — | — | **¥1** |
| 音效 / BGM | — | — | — | — | **¥84** |
| | | | | | **共约 ¥148** |

**α 的内容生成总花费约 ¥148，占 ¥2,000 预算的 7.4%。**

口径与 [`个人开发可行性.md`](./个人开发可行性.md) 第二节一致（全 TTS 配音，不含 AI 编程助手订阅）。可用率是最不确定的参数——**第 1 周只生成会议室一个场景的整图，就是去实测这个数**。

> **省钱的关键动作**：分层图不能分别文生图（会得到三个不同光线、不同透视的房间）。正确做法是**先出一张完整图**定死光线与风格，再按深度切开、沿切缝外扩 8%。32 张分层图的实际出图次数应接近 **8 张整图**，不是 32 次生成。

## 7. α 明确不碰的东西

个人项目最贵的不是做错，是**范围蔓延**。以下全部不在 α 内，写在这里是为了让你能理直气壮地说"不"：

| 不做的 | 为什么 | 什么时候做 |
|---|---|---|
| 困局回溯弹窗（M5） | 依赖完整年度循环，α 只有 3 个事件 | β |
| 5 个结局 | 只做 1 个 | β 加 3 个，1.0 补齐 |
| 20 个事件 | 只做 3 个 | β 12 个，1.0 20 个 |
| 跨年晋升评估 | α 是单季度切片 | β |
| 存档系统扩展 | 用现有基础存档即可，α 甚至可以不存 | β |
| 走路 / 开门 / 递物等动作演出 | 引擎做不了，AI 可用率仅 25% | **永远不做**，用剧本规避 |
| 多语言 | 只做中文 | 上架后看需求 |
| 主角立绘 | 第一人称，主角不露脸（见 [`对话与场景系统设计.md`](./对话与场景系统设计.md)） | 不做 |

## 8. 验收标准（什么叫"做完了"）

α 完成的定义，**必须全部满足**：

- [ ] 从主菜单进入，能一路玩到结局，**不需要手动切场景**
- [ ] 中文不出现方块 / 缺字（U0 的雷已排）
- [ ] 3 个事件全部有画面（不是纯色底），每个事件至少 8 次切镜
- [ ] 选择后能看见七维数值的变化（`StatBar` 飘字）
- [ ] 画面**任何时刻都不静止超过 2 秒**（用 `hold` 微呼吸兜底）
- [ ] 结局有 1 条视频，且视频缺失时能自动降级为静态帧而不崩
- [ ] 有声音（TTS 配音 + 至少 3 个音效）
- [ ] 打包成 Windows 可执行文件，**发到 itch.io**
- [ ] 找 3 个不玩游戏的陌生人试玩，**至少 2 人玩到结局**

> 最后一条是真正的验收。前面八条是"我做到了"，最后一条是"它成立"。

## 10. 从 α 到 1.0 的升级路径

α 的每一份资产都在 1.0 里复用，**没有一处是演示性投入**：

| α 产出 | 在 1.0 中 |
|---|---|
| 3 个场景的镜头与分层图 | 22 个场景中的 3 个，直接用 |
| 对话引擎 / 镜头导演 / AVG 界面 | 原样扩展，不用重写 |
| 3 个事件的剧本 | 20 个事件中的 3 个，改用同一套 schema |
| 4 个 NPC 的立绘 | 5 个 NPC 中的 4 个 |
| 视频层准入规则 | 8 条视频的判定标准 |

**换句话说：α 不是"为了验证而做的东西"，它就是 1.0 的前 15%。** 做 α 的成本是 ¥148 + 约 1 个月，它买到的是"一个明确的答案"——

**这比花 10 个月做一个没人要的 1.0 便宜太多。**
