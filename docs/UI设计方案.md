# 《打boss》UI 设计与实现方案

> **文档版本**：v1.0
> **状态**：方案（用户确认后进入实现）
> **关联文档**：[`职级轮回_游戏策划书.md`](./职级轮回_游戏策划书.md)（v1.1）
> **效力说明**：本文档**只管界面层**——渲染地基、视觉规范、控件拆分、场景骨架、实施顺序。
> 玩法规则、数值、事件、结局条件一律以策划书为准，本文不得与之冲突。
> **纪律**：UI 跟随 M1~M8 模块推进，**不单独先行铺全套界面**；每完成一个模块，顺手做掉它的界面。

---

## 0. 现状诊断

当前仓库的 UI 是**程序白盒**，不是"没有 UI"，而是"UI 全写在 tscn 里、没有任何设计层"。

| 现象 | 位置 | 问题 |
|---|---|---|
| 无 Theme 资源 | 全项目 | `theme_override_font_sizes/font_size = 22` 这类内联覆盖散落在每个节点，改一次字号要改 N 个文件 |
| 无中文字体 | `project.godot` | Godot 4 内置默认字体**不含完整中文字形**，中文极可能渲染成方块/空白（**第 0 颗雷，先 F5 验证**） |
| 无美术资源 | `ui/` 目录只有 `.gitkeep` | 背景是纯 `ColorRect`，无图标、无面板质感、无状态反馈 |
| 数值只有一个 Label | `day_screen.tscn` | 七维拼成一行字符串，玩家看不出"哪项在涨、涨了多少、离阈值多远" |
| 逻辑与表现耦合 | `day_screen.gd` | `_on_choice()` 里同时做结算、标记、存档、文案拼接、界面切换，UI 无法独立迭代 |
| 选项按钮写死 3 个 | `day_screen.tscn` | `BtnChoiceA/B/C` + `visible` 控制，未来 4 选项或动态选项要重构 |
| 场景切换硬编码 | `main_menu.gd` | `change_scene_to_file("res://scenes/xxx.tscn")` 散落各处，没有路由层 |

**结论**：现在缺的不是"画几张图"，而是**一条从设计系统到场景骨架的路径**。下面按 4 层给。

---

## 1. 目标与非目标

**目标（MVP 范围内）**
1. 中文在任何机器、任何分辨率下都清晰不乱码。
2. 存在一份**唯一的视觉真相**：改 Theme 一处，全 UI 生效。
3. 七维数值、年/季/周、NPC 好感**可视化**（条 + 数字 + 变化反馈），而不是一串文字。
4. 关键节点有**仪式感**：回溯、晋升、结局三个弹窗是全游戏的表演高潮。
5. UI 层与玩法层解耦：UI 只订阅信号 + 发意图，不做数值计算。

**非目标（明确不做）**
- 精美立绘、3D、粒子特效（策划书 §11 已列为非 MVP）
- 完整成就系统、多语言、语音
- 复杂派系数值盘
- 皮肤/主题切换系统

## 2. UI 分层架构

```
L4  交互与反馈   飘字 / 条动画 / 负荷屏效 / 键鼠可达 / 音效
L3  场景骨架     main_menu · mode_select · year_hub · event_popup
                 · rewind_modal · promotion_report · ending_screen
L2  组件库       StatBar · EventCard · CalendarStrip · Modal · Toast ...
L1  设计系统     game_theme.tres（字体 / 色板 / 字号层级 / 控件四态）
L0  渲染地基     中文字体 · 分辨率与缩放 · 窗口策略 · TextServer
```

**铁律：从下往上做，不跳层。** 没有 L0/L1 就直接做 L3，等于把 L1 的债复制到每个场景里（这正是现状）。

## 3. L0 渲染地基（最高优先，半天可完成）

### 3.1 中文字体（必做，否则全盘白干）

1. 下载开源可商用中文字体，放 `res://ui/fonts/`：
   - 推荐 **思源黑体 SC**（Source Han Sans SC）或 **Noto Sans SC**；正文也可选 **霞鹜文楷 / 更纱黑体** 走"文书感"。
2. **两种设置方式，选第二种**：
   - ❌ 只在 Project Settings → GUI → Theme → Default Font 填字体 → 只改了默认字体，控件样式仍无处统一。
   - ✅ 建 `game_theme.tres`（见 L1），在该 Theme 的 **Default Font / Default Font Size** 里指定字体，再把 Project Settings → `gui/theme/custom` 指向它 → 字体与全控件样式**一处管理**。
3. 中英混排若要风格一致，主字体选含拉丁字形的 CJK 字体即可；如需英文用另一字体，用 **Font Variation / fallback**，不要靠系统字体兜底（玩家机器上不一定有）。

### 3.2 分辨率与缩放

`project.godot` 现状：`1280x720` + `stretch/mode = canvas_items`。**方向是对的**，补充三点：

```ini
[display]
window/size/viewport_width=1280
window/size/viewport_height=720
window/size/window_width_override=1600     # 开发时窗口大一点便于调试
window/size/window_height_override=900
window/stretch/mode="canvas_items"          # 保持：UI 文字会按实际分辨率重新栅格化，清晰
window/stretch/aspect="expand"              # 改：超宽屏不拉伸、不加黑边，而是露出更多画布
window/stretch/scale_mode="fractional"      # 4.2+：非整数倍缩放更清晰
```

- 设计基准 **1280×720**，但所有面板必须用 **Anchor + Container** 布局，保证从 1280×720 到 3440×1440 都不塌。
- 窗口可调大小（默认开启），并提供"全屏/窗口"选项（放设置面板）。
- **不要用 `viewport` 拉伸模式**：那是把画面先渲染成固定尺寸再放大，文字会糊。

### 3.3 发布前

- 字体**子集化**（只保留用到的字符），可省 80%+ 体积；对 Steam 包体有实际意义。
- 导出设置里确认字体随包嵌入，别依赖玩家系统字体。

## 4. L1 设计系统：`ui/theme/game_theme.tres`

### 4.1 色板（冷企业色 + 一个高亮强调色）

| 语义 | 建议值 | 用途 |
|---|---|---|
| `bg_deep` | `#10141B` | 最底层背景 |
| `bg_panel` | `#171D26` | 面板/侧栏 |
| `bg_card` | `#1E2530` | 事件卡/弹窗 |
| `bg_hover` | `#252E3B` | 悬停 |
| `stroke` | `#2A333F` | 描边/分隔线 |
| `text_primary` | `#E6EBF2` | 正文 |
| `text_secondary` | `#93A0B0` | 说明/次要信息 |
| `text_disabled` | `#5A6676` | 禁用 |
| `accent` | `#3D7BFF` | 澄川蓝，主按钮/焦点/选中 |
| `positive` | `#35C48B` | 正向数值变化 |
| `warning` | `#F0A33A` | 预警（健康低、资源告急） |
| `danger` | `#E0544D` | 危险/负向 |
| `mind` | `#A46BFF` | **精神负荷专属色**（紫色，与其它维度视觉区隔） |
| `gold` | `#E8C46A` | 晋升 / CEO / 通关 |

> 规则：颜色只从这张表取，**禁止在场景里写 `Color(...)` 字面量**。现在两个 tscn 里的 `color = Color(0.12, 0.14, 0.18, 1)` 应全部迁入 Theme。

### 4.2 排版层级（用 Theme Type Variation，不要内联覆盖）

| 名称 | 字号 | 用途 |
|---|---|---|
| `Label/H1` | 36 | 界面主标题 |
| `Label/H2` | 24 | 区块标题、事件标题 |
| `Label/Body` | 18 | 事件正文 |
| `Label/Caption` | 14 | 说明、提示、时间戳 |
| `Label/Number` | 18 | **数值专用**：等宽数字（tabular figures），避免数字跳动时宽度抖动 |

建法：Theme 里右键 → *Add Type Variation* → 基于 `Label` 派生 `H1/H2/Body/Caption`，场景里设 `theme_type_variation = "H1"` 即可。**`theme_override_*` 在业务场景里应当绝迹。**

### 4.3 控件四态规范

每个交互控件必须定义 `normal / hover / pressed / disabled / focus` 五个 StyleBox：

- Button：圆角 6、`bg_card` 底、`stroke` 边；hover 换 `bg_hover` + 边色转 `accent`；focus 加 2px `accent` 外描边（**键盘可达的前提**）。
- Panel / Card：圆角 10 + 1px `stroke`，可选 4px 内阴影拉开层次。
- ProgressBar：底槽 `bg_deep`，填充按语义上色（见 §5 `StatBar`）。

## 5. L2 组件库（`ui/components/`）

用**场景 + 脚本**做成可复用组件，每个组件自己订阅 `EventBus`，对外只暴露 `set_value()`。

| 组件 | 文件 | 说明 |
|---|---|---|
| `StatBar` | `ui/components/stat_bar.tscn` | 图标 + 名称 + 进度条 + 数值 + `+4 / -3` 飘字动画。**七维全部用它**，`mind_load` 传 `mind` 色 |
| `StatPanel` | `ui/components/stat_panel.tscn` | 7 个 `StatBar` 的容器，订阅 `EventBus.stats_changed` 整体刷新 |
| `CalendarStrip` | `ui/components/calendar_strip.tscn` | 12 格（4 季 × 3 周）进度条，当前格高亮，**是"轮回"最直观的具象化** |
| `EventCard` | `ui/components/event_card.tscn` | 标签 chips + 标题 + 正文 + **动态生成的**选项列表 + 结果区 |
| `ChoiceButton` | `ui/components/choice_button.tscn` | 单条选项；hover 升高、按下有位移；支持"需要条件未满足"的灰态与提示 |
| `NpcFavorRow` | `ui/components/npc_favor_row.tscn` | 头像位 + 姓名 + 好感条（0~100，60/55/50 处打刻度线，一眼看出是否够"庇护门槛"） |
| `Modal` | `ui/components/modal.tscn` | 通用遮罩弹窗：标题 + 内容 + 1~2 按钮，带淡入缩放动画 |
| `Toast` | `ui/components/toast.tscn` | 左下角飘出"已自动存档 / 好感 +6"等轻提示 |
| `SceneRouter` | `autoload/scene_router.gd` | 统一 `goto(SceneId)`，内部维护路径表与切换过渡 |

**`StatBar` 是投入产出比最高的组件**——七维、NPC 好感共用一套逻辑，做完它整个游戏的"数值可读性"问题就解决了。

## 6. L3 场景骨架

### 6.1 `year_hub`（年度回合主界面，全游戏最重要的一屏）

把 `day_screen.tscn` 演进为三栏结构：

```
┌──────────────────────────────────────────────────────────┐
│ 澄川控股 · 第 1 年 Q2 W3   [回溯模式]           [设置][存档] │ 顶栏 64
├───────────────┬──────────────────────────────────────────┤
│ 七维面板        │  事件区                                   │
│ 绩效  ████░ 42 │  「周报扩写运动」  #形式主义                │
│ 专业  ███░░ 35 │  ─────────────────────────────           │
│ 人脉  ██░░░ 20 │  部门要求周报从「三句话」扩成「一页纸…」     │
│ 声望  ██░░░ 25 │                                          │
│ 负荷  ░░░░░  0 │  ┌────────────────────────────────────┐  │
│ 健康  █████ 80 │  │ ① 堆砌漂亮空话交差                   │  │
│ 资源  ¥ 3000   │  │ ② 只写可验证事实与风险               │  │
│ ─────────────  │  │ ③ 联合几人提议恢复短周报             │  │
│ NPC 好感        │  └────────────────────────────────────┘  │
│ 沈听澜 ███░ 40 │                                          │
│ 季  衡 ███░ 35 │                                          │
├───────────────┴──────────────────────────────────────────┤
│ 12 格日历条  ■■■■■■■□□□□□            [开始本周 →]          │ 底栏 72
└──────────────────────────────────────────────────────────┘
```

要点：
- 左栏固定宽（约 260），右栏 `size_flags_horizontal = 3` 撑满，事件正文 `autowrap` 自动换行。
- `event_popup` **不单独做弹窗**——主界面内联显示事件；只有"回溯确认 / 晋升报告 / 结局"才用真弹窗。减少一次界面跳转，节奏更顺。
- 事件正文区高度自适应，选项由 `EventCard` 动态生成，**不再写死 A/B/C 三个按钮**。

### 6.2 `main_menu`
标题 + 副标题 + 4 个按钮（新游戏·普通 / 新游戏·回溯 / 继续 / 退出）+ 右下角版本号；结局图鉴列为灰态占位。有存档时"继续"高亮并显示"第 N 年 · 职级"摘要。

### 6.3 `mode_select`（新建）
两张并排卡片，不是普通按钮列表——因为这是**玩法契约**，必须让玩家读懂：

| 普通模式 | 回溯模式 |
|---|---|
| 失败即终局（职场淘汰） | 重大失败可回到本年度年初，保留记忆与情报 |
| 无回溯惩罚 | 每次回溯 **精神负荷永久 +12 / +16 / +20** |
| 面向挑战 / 速通 | 面向叙事 / 探索最优路径 |

选中卡片描边转 `accent`，底部"开始"按钮才可点。

### 6.4 `rewind_modal`
全游戏表演性最强的一屏。建议：
1. 遮罩渐暗 → 画面整体轻微 **RGB 偏移 / 扫描线抖动**一帧；
2. 日历条**从右往左倒卷**回 W1；
3. 中央弹出："回到本年度第 1 周？代价：精神负荷 +12（0 → 12）"；
4. 按钮：`执行困局回溯`（accent）/ `接受结果`（danger）。
5. 若 `mind_load + penalty >= 100`，按钮直接灰掉并提示"负荷将满，回溯即沉沦"。

### 6.5 `promotion_report`
年末仪式感。不要只给一句"升职成功"，要给出**可复盘的账本**：

```
第 1 年 绩效评估
────────────────────────────
评估得分  58.4   （晋升线 52.0）✅
绩效 42×0.35 = 14.7   （硬门槛 ≥50）❌
专业 35×0.25 =  8.8   （硬门槛 ≥40）❌
人脉 20×0.15 =  3.0
声望 25×0.15 =  3.8
健康 80×0.10 =  8.0
精神负荷惩罚  -0.0
NPC 支持加成  +6.0
────────────────────────────
晋升判定：未通过 —— 专业能力差 5 点
```

这直接对应策划书 §5.2 / §5.3 的公式与硬门槛表，UI 只需**照表渲染**，逻辑全在 M4 的 `PromotionService` 里。

### 6.6 `ending_screen`
五结局共用模板：结局编号 + 副标题（如"登顶 CEO · 破局"）+ 正文文案 + 一屏**生涯回顾**（初始→最终七维对比条、回溯次数、关键 flag）+ `返回主菜单` / `结局图鉴`。结局配色：破局=金、沉沦=紫、轮回=紫、离场=青、淘汰=灰。

## 7. L4 交互与反馈规范

1. **数值变化必须有反馈**：条位移动画（0.35s ease-out）+ `+4` 飘字（向上淡出 0.8s）。没有动画，玩家根本感知不到自己做了什么。
2. **选择前不给数值预判**（保持叙事张力）；**选择后给完整结算面板**（这次哪些项变了、变多少，逐项列出）。
3. **键盘可达**：`↑↓` 切换选项、`Enter` 确认、`Esc` 关闭弹窗、`1/2/3` 直选。文字游戏玩家会长时间坐在椅子上，键盘流是刚需。
4. **禁用态永远带原因**：`tooltip` 或小字说明"需要唐破晓好感 ≥50"。只灰掉不给理由会让玩家觉得游戏坏了。
5. **自动存档要有存在感**：每次结算后 `Toast` 提示"已自动存档"，玩家才敢做高风险选择。
6. **精神负荷的屏效**（性价比最高的机制可视化，非 MVP）：
   - `mind_load ≥ 40`：屏幕四角极淡暗角；
   - `≥ 70`：暗角加深 + 文字偶发 1px 抖动 + 轻微色偏；
   - `≥ 90`：低概率一帧扫描线撕裂。
   零美术成本，却让"精神负荷"从数字变成体感。

## 8. 代码落点与重构建议

| 事项 | 落点 |
|---|---|
| 主题资源 | `ui/theme/game_theme.tres`（+ 字体 `ui/fonts/`、图标 `ui/icons/`） |
| 组件 | `ui/components/*.tscn` + `*_row.gd` |
| 场景路由 | `autoload/scene_router.gd`（新，替换散落的 `change_scene_to_file`） |
| 界面骨架 | `scenes/main_menu.tscn`、`scenes/mode_select.tscn`、`scenes/year_hub.tscn`、`scenes/ending_screen.tscn` |
| 表现层脚本 | 各 `*.gd` 只做"渲染 + 收集输入" |

**关键重构：把结算逻辑从 UI 里拿出来。**
现在 `day_screen.gd::_on_choice()` 干了太多事。建议在 `GameState`（或新的 `ChoiceResolver`）里加：

```gdscript
## 返回本次选择的结算摘要，供 UI 渲染；UI 不参与任何数值计算
func resolve_choice(event: Dictionary, index: int) -> Dictionary:
	# 内部完成 apply_deltas / npc_effects / flags / 记录已触发事件
	# 返回形如 { "deltas": {...}, "npc_changes": {...}, "flags": [...], "fatal": false }
```

UI 侧变成纯粹的：

```gdscript
var summary := GameState.resolve_choice(_current_event, index)
_event_card.show_result(summary)   # 只负责显示
```

这样做的收益：UI 可以独立改版而不动玩法；玩法可以加自动化测试（`smoke_test.gd`）而不依赖节点树。

**另一条建议：选项按钮改为动态生成。**
`EventCard` 里 `for i in choices.size(): var b = ChoiceButton.instantiate(); ...`，彻底摆脱 A/B/C 写死。

## 9. 实施顺序与验收标准

| 步骤 | 内容 | 依赖 | 验收标准 |
|---|---|---|---|
| **U0** | 中文字体 + 缩放策略 + 窗口策略 | 无 | 任意分辨率下中文无方块、无糊字；窗口拉伸布局不塌 |
| **U1** | `game_theme.tres` 设计系统 + `StatBar` 组件 | U0 | 全项目 `theme_override_*` 清零；改 Theme 一处，字号/颜色全局生效 |
| **U2** | `year_hub` 三栏重构（七维面板 + 日历条 + 事件卡 + 动态选项） | U1 | 主界面具备"游戏感"；数值变化有动画与飘字 |
| **U3** | `mode_select` + `promotion_report` | U1 | 模式选择能讲清两种玩法差异；年末评估逐项可复盘 |
| **U4** | `rewind_modal` + `ending_screen`（随 M5/M7 一起做） | U3、M5、M7 | 回溯有倒卷动效；五结局各有独立配色与回顾页 |
| **U5** | 负荷屏效 + 音效 + 设置面板 + 键盘流抛光 | U4 | EA 准备 |

**与现有里程碑的对齐**：α1（M1+M2+M3）→ 完成 U0/U1/U2；α2（M4+M6）→ U3；α3（M5）→ U4 的回溯部分；β2（M7）→ U4 的结局部分；EA → U5。
