## 2. 世界观设定（原创）

### 2.1 背景

玩家就职于虚构民营集团 **「澄川控股」**（Chengchuan Holdings），总部位于沿海二线城市「澄川市」。集团业务覆盖：企业数字化服务、智慧物流、城市运营咨询三大板块。对外口号是「让组织更高效」；对内则是绩效数字化、汇报流程化、部门壁垒化。

澄川控股并非反派公司，而是一面镜子：制度看起来合理，执行起来却常常把人磨成零件。玩家要在规则缝隙里活下去，并决定自己成为什么样的人。

### 2.2 关键设定

- **时间尺度**：游戏以「年」为最大循环单位；每年含 **4 个季度**；每季度含 **3 个工作周**（抽象回合，非真实日历）。  
  → 一年 = 12 个回合（决策节点）。每年年末进行 **年度绩效评估与晋升窗口**。
- **困局回溯（核心幻想）**：回溯模式下，玩家遭遇「重大职业失败」时，可选择将意识拉回 **本年度第 1 周开头**。他人不知回溯发生；玩家记得失败原因与关键信息。代价是 **精神负荷永久 +N**（见数值规则）。
- **记忆保留范围**：回溯后保留——当前职级、7 项数值中「精神负荷」的累加、已解锁的情报标记、与 NPC 的「隐式印象修正」；重置——本年度已触发的事件、本年度季度进度、本年度临时 Buff/Debuff、本年度绩效结算标记。

### 2.3 派系与组织（浅层，供事件引用）

| 派系 | 倾向 | 玩家影响 |
|---|---|---|
| 业绩派 | 结果导向、加班文化 | 易涨绩效/专业，易伤身心健康 |
| 关系派 | 人情、站队、信息差 | 易涨人脉/声望，易卷入流言 |
| 改革派 | 引入 AI、流程再造 | 短期冲击岗位安全感，长期影响专业路径 |
| 中立求生 | 大多数基层 | 默认立场；站队事件会迫使选择 |

MVP 不强制完整派系系统，仅在事件/NPC 对话中体现标签，为后续扩展留钩子。

## 3. 玩法总览

### 3.1 主循环

```
主菜单 → 选择模式（普通/回溯）→ 新游戏
    ↓
【年度循环】
  年初：展示目标 / 精神负荷状态 / NPC 简讯
  → 进入第 Q 季第 W 周
      → 抽取 1 个主事件（可叠加 0~1 个轻量插曲，MVP 可只做主事件）
      → 玩家选择 → 结算 7 维数值 + NPC 好感（若涉及）
      → 检查：是否触发重大失败？是否身心健康归零？是否精神负荷满值？
      → 推进下一周；季度末小结算；年末大结算 + 晋升判定
  → 若晋升至 CEO：进入结局分支判定
  → 否则进入下一年（职级保留，部分数值衰减/恢复规则见 §5）
```

### 3.2 两种模式差异

| 规则 | 普通模式 | 回溯模式 |
|---|---|---|
| 被辞退 / 重大项目事故 | **直接进入「职场淘汰结局」**（或失败结算） | 弹出「困局回溯」选项 |
| 困局回溯 | 不可用 | 可回到本年度年初 |
| 精神负荷 | 仍可通过负面事件上涨，但 **无回溯加成**；满值仍可触发沉沦相关结局 | 每次回溯永久 +负荷；满值 → **困局沉沦结局** |
| 推荐受众 | 硬核/速通/挑战 | 叙事向/探索最优路径 |

### 3.3 「重大职业失败」定义（可触发回溯选项）

满足任一即可（回溯模式）：

1. **被辞退**：绩效过低 + 无关键 NPC 庇护，或连续 2 次年度评估「不达标」且资源储备不足以「缓冲」。  
2. **重大项目事故**：某事件选项导致「事故标记」且绩效/声望暴跌至阈值（见事件标签 `fatal_fail`）。  
3. **软裁员落地**：变相调岗事件链走完，岗位被取消（事件链标记 `soft_layoff_done`）。

普通模式下，上述情况直接导向失败类结局，不给回溯。

### 3.4 胜利与失败（概览）

- **通关主线**：职级升至 **CEO**。  
- **通关后分流**：根据精神负荷、身心健康、声望、人脉等判定「破局」或「沉沦」结局（见 §7）。  
- **非 CEO 终局**：困局沉沦 / 清醒离场 / 职场淘汰（见 §7）。

## 4. 角色七项核心数值

所有数值均为整数。UI 显示建议用条+数字。

| 键名（代码） | 中文 | 范围 | 初始（实习生） | 说明 |
|---|---|---|---|---|
| `performance` | 绩效 | 0~100 | 40 | 年度评估核心；事件中最常见涨跌项 |
| `expertise` | 专业能力 | 0~100 | 35 | 晋升硬门槛；培训/项目类事件提升 |
| `influence` | 人脉影响力 | 0~100 | 20 | 跨部门协作、站队、庇护 |
| `reputation` | 声望 | 0~100 | 25 | 公开形象；流言/甩锅/庆典影响大 |
| `mind_load` | 精神负荷 | 0~100 | 0 | **回溯专属累加主轴**；满值危险 |
| `health` | 身心健康 | 0~100 | 80 | 归零触发强制离场相关判定 |
| `resource` | 资源储备 | 0~999999 | 3000 | 金钱/可用资源；可为负时钳制到 0（MVP） |

### 4.1 通用结算规则

```text
apply_delta(stat, delta):
  if stat == mind_load:
      value = clamp(value + delta, 0, 100)   # 回溯带来的增加视为永久，不提供自然下降（见下）
  elif stat == health:
      value = clamp(value + delta, 0, 100)
  elif stat == resource:
      value = max(0, value + delta)
  else:
      value = clamp(value + delta, 0, 100)
```

### 4.2 自然恢复与衰减（年末）

| 数值 | 年末规则（MVP） |
|---|---|
| 绩效 | 重置为 `40 + rank_index * 3`（体现职级预期），再叠加本年结余修正（±10 内） |
| 专业能力 | 不变（永久成长） |
| 人脉影响力 | `-5`（关系需维护），不低于 0 |
| 声望 | `-3` |
| 精神负荷 | **不自然下降**（唯有极少数「疗愈类」事件可 -1~-3，且有次数上限） |
| 身心健康 | `+10`（休假恢复），不超过 100 |
| 资源储备 | `+ 职级年薪津贴`（见职级表） |

### 4.3 精神负荷特殊规则

- 普通模式：事件可增减；无「回溯 +负荷」。  
- 回溯模式：每次成功执行困局回溯 → `mind_load += rewind_penalty`。  
  - 第 1 次回溯：`+12`  
  - 第 2 次：`+16`  
  - 第 3 次及以后：`+20`（可配置）  
- `mind_load >= 100`：立即触发 **【困局沉沦结局】**（回溯模式）；普通模式改为强负面状态并大幅提高淘汰权重（MVP 可同样直接结局，简化）。  
- 精神负荷对玩法的持续影响：  
  - `mind_load >= 40`：负面事件权重 ×1.25  
  - `mind_load >= 70`：负面事件权重 ×1.6，晋升评估 **额外 -8 分**  
  - `mind_load >= 90`：每回合开始有概率追加「焦虑插曲」（MVP 可简化为固定小幅 health/performance 惩罚）

| 7 | CEO | — | 通关职级 |

### 5.2 晋升窗口

- **仅在每年年末评估**通过后，若满足下一职级门槛，则晋升 1 级（一年最多升 1 级，防崩数值）。  
- 评估得分公式（MVP）：

```text
eval_score =
    performance * 0.35
  + expertise   * 0.25
  + influence   * 0.15
  + reputation  * 0.15
  + health      * 0.10
  - mind_load_penalty          # 见 §4.3
  + npc_support_bonus          # 关键 NPC 好感达标时 +0~15
```

- `eval_score >= 晋升线` 且满足「硬门槛」→ 晋升。  
- `eval_score < 淘汰线` → 记一次「不达标」；连续 2 年不达标 → 重大失败（辞退流程）。

## 6. 五名原创 NPC

> 设计原则：姓名、经历、口癖、冲突点全部原创；避免「假高管亲戚替班」「年会翻车反转」等标志性影视桥段作为角色核心卖点。

### 6.1 沈听澜 — 集团战略办公室主任

| 项 | 内容 |
|---|---|
| 年龄外貌 | 42 岁，短发，着装极简，语速稳定 |
| 背景 | 咨询公司出身空降澄川，负责战略对齐与「组织健康度」指标；不被业务线待见，却握有晋升委员会一票 |
| 性格 | 理性、克制、厌恶无效会议；对诚实的数据比好听的汇报更感兴趣 |
| 价值观 | 「流程是用来减少伤害的，不是用来表演的」 |
| 互动逻辑 | 好感↑：玩家在形式主义事件中选择「删减废话、给真实风险」；好感↓：玩家选择「美化数据/空洞汇报」 |
| 庇护能力 | 好感≥60：年度不达标时可减免 1 次辞退判定 |
| 对立面 | 与「季衡」在是否激进上 AI 替换人力上意见不合 |

### 6.2 季衡 — 数字化事业部副总经理

| 项 | 内容 |
|---|---|
| 年龄外貌 | 38 岁，眼镜，常年端咖啡，说话带点推销感 |
| 背景 | 内部提拔的技术转管理；推动「灵析」AI 助手进各部门，背着总部降本指标 |
| 性格 | 外热内冷，擅长把争议包装成「趋势」；并非恶意，但常低估人的焦虑 |
| 价值观 | 「不拥抱变化的人会被变化拥抱」 |
| 互动逻辑 | 好感↑：参与 AI 试点、提出可落地的人机协作方案；好感↓：公开抵制数字化却拿不出替代方案 |
| 庇护能力 | 好感≥55：专业类事件额外 +expertise 机会；AI 冲击事件中可解锁「转岗培训」分支 |
| 对立面 | 基层视其为裁员推手；沈听澜要求他提交「人员冲击评估」 |

### 6.3 尤晩星 — 人力资源业务伙伴（HRBP）

| 项 | 内容 |
|---|---|
| 年龄外貌 | 33 岁，声线轻，记录习惯极好 |
| 背景 | 从校园招聘做起，经手过多轮「优化」；表面温和，实则清楚每条制度的灰色地带 |
| 性格 | 倾听型；很少给承诺，但给的承诺会兑现 |
| 价值观 | 「我不能改变规则，但我可以告诉你规则怎么咬人」 |
| 互动逻辑 | 好感↑：玩家不把同事当枪使、不主动造谣；好感↓：利用流言整人、或在合规问题上撒谎 |
| 庇护能力 | 好感≥50：软裁员/调岗事件可提前获得「风险提示」；好感≥70：可降低一次辞退概率 |
| 特殊 | 掌握「绩效校准会」的隐性信息，年末评估前可能触发私聊事件 |

### 6.4 唐破晓 — 智慧物流线项目经理（同级/可升迁竞争者）

| 项 | 内容 |
|---|---|
| 年龄外貌 | 29 岁，运动外套塞进工牌，走路快 |
| 背景 | 和玩家同期入职的「高潜」；交付能力强，但不擅长向上管理；常与玩家抢资源/功劳 |
| 性格 | 直球、好胜、重承诺；被背叛会记仇，但被帮过会加倍还 |
| 价值观 | 「事情做成比会议开完重要」 |
| 互动逻辑 | 好感↑：项目成果纠纷中选择公平署名/主动担责帮其解围；好感↓：抢功、甩锅 |
| 庇护能力 | 好感≥65：跨部门协作事件成功率上升（抽象为 performance/expertise 额外加成） |
| 竞争 | 同职级时，其绩效高会挤占有限晋升名额（MVP：年末若唐破晓好感<40 且玩家绩效仅卡线，晋升线 +5） |

### 6.5 梁叙 — 行政与企业文化负责人

| 项 | 内容 |
|---|---|
| 年龄外貌 | 45 岁，笑容职业，总能叫出人名 |
| 背景 | 老澄川人，负责庆典、内刊、表彰；看似「搞活动的」，实则是关系派与业绩派之间的润滑剂 |
| 性格 | 圆滑、观察力强；不轻易站队，但会记住谁在公开场合给过体面 |
| 价值观 | 「场面要圆，人心要留」 |
| 互动逻辑 | 好感↑：年度庆典/公开场合选择体面、不让同事难堪；好感↓：当众拆台、把庆典当整人舞台 |
| 庇护能力 | 好感≥60：声望类危机可缓和；解锁「非公开沟通」选项 |
| 注意 | 庆典事件是其主场，但内容聚焦「表彰指标化、形式主义发热」，**不**做成影视式大型翻车桥段复刻 |

### 6.6 NPC 好感通用规则（MVP）

- 每名 NPC：`favor` 0~100，初始 40（唐破晓初始 45，季衡 35）。

## 7. 五套完整结局

### 7.1 【登顶 CEO · 破局结局】

**一句话**：你坐上最高位，却选择把刀收起来，推动可执行的改革。

**触发条件**（需全部满足）：

1. `rank_index == 7`（已成为 CEO）  
2. `mind_load <= 55`  
3. `health >= 40`  
4. `reputation >= 70` 且 `influence >= 70`  
5. 至少 2 名核心 NPC 好感 ≥ 60  
6. 关键标记：生涯中至少 1 次在「形式主义/甩锅/软裁员」类事件中选择过「护人/揭风险」正向选项（`flag_reform_seeds >= 1`）

**结局倾向文案要点**：设立透明评估试点、限制无效汇报时长、给被 AI 冲击的岗位转型预算……你仍在体制内，但轮回的齿轮松了一扣。

---

### 7.2 【登顶 CEO · 沉沦结局】

**一句话**：你赢了规则，也被规则写成了另一种人。

**触发条件**：

1. `rank_index == 7`  
2. 满足以下 **任一**：  
   - `mind_load >= 70`  
   - `health < 40` 且 `reputation >= 75`（高声望低健康：靠透支换来的顶峰）  
   - `flag_reform_seeds == 0` 且 `flag_dark_choices >= 3`（多次选择站队整人/甩锅/美化数据）  
3. 未同时满足「破局结局」全部条件（破局优先）

**结局倾向文案要点**：澄川更高效了，也更冷了。你想起回溯里那些本可不同的一周，终于不再回头。

---

### 7.3 【困局轮回结局】（困局沉沦）

**一句话**：记忆叠成牢笼，你在同一年里走不出去。

**触发条件**：

1. 游戏模式为 **回溯模式**  
2. `mind_load >= 100`  
3. 或：单局回溯次数 `rewind_count >= 5` 且 `mind_load >= 85`（防卡死的保底沉沦）

**结局倾向文案要点**：同事的对话你已听过太多次；你甚至能预判咖啡机的故障日。所谓经验，变成无法卸载的噪音。

---

### 7.4 【清醒离场结局】

**一句话**：你看清了轨道，选择下车。

**触发条件**（满足任一路径）：

**路径 A — 主动离职**

1. `rank_index` 在 1~5 之间  
2. 玩家在特定事件（如「外部机会」「身心警报」）选择「离职」  
3. `health >= 20` 且 `resource >= 5000`（有基本再出发条件）  
4. `mind_load < 100`

**路径 B — 健康强制清醒**

1. `health <= 5` 且未触发辞退流程的同一回合  
2. 弹出强制「就医/离职」选择；选离职或连续忽略导致自动离场  
3. `mind_load < 100`

**结局倾向文案要点**：没有登顶，但你带走了技能、积蓄，以及 intact 的一部分自己。澄川的灯火还在，只是不再是你的考场。

---

### 7.5 【职场淘汰结局】

**一句话**：系统把你标记为可替换项。

**触发条件**（满足任一）：

1. **普通模式**下发生重大职业失败（辞退/事故/软裁员落地）  
2. **回溯模式**下玩家在回溯弹窗选择「放弃回溯，接受结果」  
3. 连续 2 年评估不达标且无 NPC 庇护  
4. `resource == 0` 且连续 3 回合 `performance < 30`（抽象为耗尽缓冲）  
5. `health == 0` 且未走「清醒离场」路径（视为垮掉后被优化）

**结局倾向文案要点**：工牌停用比通知信更早到达。你在电梯镜里看见一个普通的失败者——以及一种奇怪的轻松。

---

### 7.6 结局优先级（同一时刻多条件）

```text
1. mind_load >= 100            → 困局轮回结局
2. rank == CEO                 → 破局 / 沉沦（破局优先）
3. 主动/强制离场条件           → 清醒离场
4. 其余失败                    → 职场淘汰
```

- **id**: `health_alarm_checkup`  
- **痛点**: 过劳与健康  
- **正文**: 体检提示睡眠与焦虑指标异常。医生建议停转，上级却丢来「关键节点」。

# 第二部分：MVP 最小原型开发方案

## 11. MVP 目标（必须可玩）

玩家能：选择模式 → 进行若干周事件 → 看到七维数值变化 → 年末晋升判定 →（回溯模式）在失败时回溯并增加精神负荷 → 存读档 → 至少打出 1 种结局（可用作弊/测试按钮触发）。

**非 MVP**：精美美术、完整 Steam 成就、复杂派系数值盘、语音、多语言。

## 12. 模块拆分与开发顺序

| 顺序 | 模块 ID | 模块名 | 依赖 | 完成定义 |
|---|---|---|---|---|
| 1 | M1 | 角色数值管理 `GameState` 七维 | 无 | 可 apply_deltas、clamp、信号刷新 |
| 2 | M2 | 年度回合推进 | M1 | year/quarter/week 推进与年末回调 |
| 3 | M3 | 事件弹窗系统 | M1,M2 | JSON 加载、过滤、2~3 选项结算 |
| 4 | M4 | 晋升判定逻辑 | M1,M2 | 评估分+硬门槛，升 1 级 |
| 5 | M5 | 困局回溯机制 | M1,M2,模式 | 失败弹窗、回年初、负荷惩罚 |
| 6 | M6 | 存档读档 | M1~M5 | save/load 字段完整 roundtrip |
| 7 | M7 | 结局判定 | M1~M6 | 五结局条件与界面 stub |
| 8 | M8 | NPC 好感（薄） | M3 | favor 读写与事件挂钩 |

**原则：一次只实现一个模块；模块合并进主分支前必须按该模块测试方法自测通过。**

### 13.2 M1 — 角色数值管理（优先实现）

```gdscript
# autoload/game_state.gd  —— 模块 M1 核心片段（示意）
extends Node
## GameState：玩家进度与七维数值
## M1 范围：数值定义、apply_deltas、初始化、只读职级名
## 非 M1：先保留旧字段或标记 deprecated，下个模块再删干净

const SAVE_PATH := "user://save.json"

## 职级链（策划书 §5）
const RANKS: Array[String] = [
	"实习生", "专员", "高级专员", "部门主管",
	"事业部经理", "区域总监", "集团副总裁", "CEO",
]

## 游玩模式
enum Mode { NORMAL, REWIND }

var mode: Mode = Mode.NORMAL

## —— 七维数值 ——
var performance: int = 40
var expertise: int = 35
var influence: int = 20
var reputation: int = 25
var mind_load: int = 0
var health: int = 80
var resource: int = 3000

var rank_index: int = 0
var year: int = 1
var quarter: int = 1
var week: int = 1
var rewind_count: int = 0

## 标记与 NPC（M7/M8 会用；M1 先给空壳避免后期大改存档）
var flags: Array[String] = []
var npc_favors: Dictionary = {}  # npc_id -> int
var year_triggered_events: Array[String] = []
var eval_fail_streak: int = 0

var job_title: String:
	get:
		return RANKS[clampi(rank_index, 0, RANKS.size() - 1)]


func _ready() -> void:
	_ensure_npc_defaults()


func _ensure_npc_defaults() -> void:
	## 五名核心 NPC 初始好感（策划书 §6.6）
	var defaults := {
		"shen_tinglan": 40,
		"ji_heng": 35,
		"you_wanxing": 40,
		"tang_poxiao": 45,
		"liang_xu": 40,
	}
	for k in defaults.keys():
		if not npc_favors.has(k):
			npc_favors[k] = defaults[k]


## 将策划 effects 字典应用到七维（M1 主 API）
func apply_deltas(deltas: Dictionary) -> void:
	performance = _clamp_stat(performance + int(deltas.get("performance", 0)))
	expertise = _clamp_stat(expertise + int(deltas.get("expertise", 0)))
	influence = _clamp_stat(influence + int(deltas.get("influence", 0)))
	reputation = _clamp_stat(reputation + int(deltas.get("reputation", 0)))
	mind_load = _clamp_stat(mind_load + int(deltas.get("mind_load", 0)))
	health = _clamp_stat(health + int(deltas.get("health", 0)))
	resource = maxi(0, resource + int(deltas.get("resource", 0)))
	EventBus.stats_changed.emit()


func _clamp_stat(v: int) -> int:
	return clampi(v, 0, 100)


func add_flag(flag: String) -> void:
	if not flags.has(flag):
		flags.append(flag)


func new_game(p_mode: Mode = Mode.NORMAL) -> void:
	mode = p_mode
	performance = 40
	expertise = 35
	influence = 20
	reputation = 25
	mind_load = 0
	health = 80
	resource = 3000
	rank_index = 0
	year = 1
	quarter = 1
	week = 1
	rewind_count = 0
	flags.clear()
	year_triggered_events.clear()
	eval_fail_streak = 0
	npc_favors.clear()
	_ensure_npc_defaults()
	EventBus.stats_changed.emit()
	EventBus.calendar_advanced.emit(year, quarter, week)
```

#### M1 测试方法

1. Godot 中运行或 headless：`apply_deltas` 后七维是否按 clamp 规则变化。  
2. `resource` 减到负应回 0；`mind_load` 不超过 100。  
3. `new_game` 后 NPC 好感恢复默认。  
4. 扩展 `smoke_test.gd`：断言初始值与一次 deltas roundtrip。

## 15. 开发纪律（给后续对话用）
