# 《打boss》静态帧影像规格（Visual Spec）

> 适用路线：**画面 = 静态帧 + 引擎动效（《隐形守护者》）｜题材 = 规则叙事（《诡舍》）｜视频仅用于结局独白与立场反转（可灵数字人）**
> 本文是这份路线图的可执行版本。它回答一个问题：**照着做，第一步动手的是什么。**
> 配套文件：`data/shots.json`（镜头表）、`scripts/shot_director.gd`（镜头导演）、`tools/shotlist.py`（拍摄单生成器）、`docs/拍摄单.md`（自动生成）

---

## 0. 一句话定义这条路线

**把"演出"从「AI 生成动态画面」搬到「引擎驱动静态画面」；把"题材"从「细腻情感」搬到「规则与信息」。**

你付钱买的是**构图和信息**，不是**动作**。这个转向一旦完成，后面所有工序都会变便宜，而且便宜的同时质量反而更稳——因为 AI 最不可靠的那一项（连续运动中的形态稳定性）被整条链路绕开了。

---

## 1. 三个必须先接受的技术事实

这三条不是建议，是约束。后面所有做法都是它们的推论。

### 1.1 Godot 4 核心只支持 Ogg Theora（`.ogv`）

不支持 H.264 / H.265（专利），不支持 WebM（4.0 起移除）。而且 Theora 是**纯 CPU 解码，没有硬件加速**。官方建议桌面端最高 1080p / 30fps。

**推论**：可灵返回的 MP4 全部要转码。这不是"后期再说"的事，要写进流水线：

```bash
ffmpeg -i in.mp4 -c:v libtheora -q:v 8 -c:a libvorbis -q:a 5 -r 30 out.ogv
```

质量不满意时的备选方案在 §5.4。

### 1.2 「一张图 = 无限镜头」的前提是出图分辨率是设计分辨率的 2 倍

项目设计分辨率 `1280×720`，所以**素材出图规格定为 `2560×1440`**。

原因：不同景别不是靠重新生成，而是靠**从同一张图里裁切**——全景裁成中景、中景裁成特写。裁到 1/2 面积后还剩 1280×720，刚好等于设计分辨率。如果按 1024 出图，裁出来的"特写"就是糊的。

这一条直接决定了 §2 的所有规格。**它是"静态帧"和"看起来像 PPT"之间的分界线。**

### 1.3 可灵数字人是「图 + 音 → 口型视频」，输入图就是你的静态立绘

`providers/avatar_kling.py::talking_head(image_path, audio_path)` —— 它拿一张图 + 一段配音，输出对口型视频。**它不重新生成人物。**

**推论（这是整份方案里最重要的一条）**：AI 视频"人物跨镜头不一致"这个行业最大痛点，在你的路线里被**结构性消除**了。因为根本不存在"AI 自由生成的人物"——只有：

- 一张角色定妆静帧
- 它的多种构图裁切（引擎做）
- 少量由这张图派生的口型视频（可灵做）

**脸永远是同一张脸。** 主流 AI 互动影游在写实路线里烧钱解决的正是这个问题，而你通过"做减法"直接绕过了它。

## 2. 素材规格

### 2.1 分层规范（分层不是美术偏好，是技术前提）

**整张图只能整体缩放——那看起来就是 PPT。** 要让画面有纵深，必须能分开动。四个深度层：

| 层名 | 内容 | 视差系数 | 举什么例子 |
|---|---|---|---|
| `far` | 远景 | 0.22 | 窗外城市、走廊尽头、天花管线 |
| `mid` | 中景 | 0.50 | 房间主体、桌椅陈设、墙 |
| `near` | 近景 | 0.80 | 靠镜头的家具、隔断、玻璃反光 |
| `over` | 前景遮挡 | 1.00 | 文件堆、门框、显示器背面、别人的肩 |

不是每个镜头都要四层。**静物特写只要一层（`mid`）**，定场全景建议三层（far/mid/near），反打镜头用 far + mid + over（`over` 就是"别人的肩"，一个纯黑或暗色剪影块也行，成本极低但纵深效果最强）。

### 2.2 出图规格

| 项 | 值 | 原因 |
|---|---|---|
| 尺寸 | `2560 × 1440` | §1.2 |
| 画幅 | 16:9 | 与设计分辨率一致 |
| 构图余量 | **四周留 8% 可裁切余量** | 引擎推拉平移最大吃掉约 15% 屏宽，贴边的关键信息会被切掉 |
| 格式 | PNG（无损） | JPEG 压缩在暗部会出现色块，压暗层会放大这个问题 |
| 单图层最大位移 | 见 §3.2 的过扫公式 | 校验脚本会拦 |

### 2.3 目录与命名

```
assets/
  shot/{scene_id}/{shot_id}_{layer}.png      # 场景分层图
  sprite/{npc_id}/{npc_id}_{emotion}.png     # 立绘
  clip/{shot_id}.ogv                         # 视频层（转码后）
```

命名规则与 `data/shots.json` 里的路径**逐字对应**。不用自己记——`python tools/shotlist.py` 会把完整清单打出来（`docs/拍摄单.md`）。

### 2.4 分层图怎么做（这一步最容易做错）

**错误做法**：对 far / mid / near 各写一次文生图提示词，分别生成。

**为什么错**：三次生成 = 三次风格漂移，光线方向、透视、色温全对不上，叠起来是三个不同的房间。

**正确做法**：

1. **先出一张完整场景图**（2560×1440），这张图定死这个场景的光线、透视、色调、风格。
2. **把它按深度切开**。切法从简到繁：
   - **最省事**：把"会随镜头移动、且需要在远处层之上的东西"抠出来当一层（比如桌上的文件堆、前景的门框）。剩下的整块当 `mid`。
   - **标准**：切 far / mid / near 三块。
3. **补边**。每层沿切缝向外扩 8%（内容用克隆图章、边缘拉伸，或用 inpainting 让 AI 补）。因为 overscan 只有 6~15%，**你只需要补"运动时会露出来的那一条边"**，工作量比想象小得多。

**一个可以省掉一半工作的技巧**：`over` 层（前景遮挡）可以干脆用纯色/暗剪影块——它本来就该是暗的、虚的、没有细节的。它承担的是"纵深"和"框住视线"两个功能，不承担信息。

### 2.5 立绘规格

**只出正面定妆一套，不做多角度。** 这是 §1.3 的直接推论：既然视频由立绘驱动，多角度没有意义。

- 每角色一张全身/半身定妆（2560 高以上）
- 表情用**同一张图的局部重绘**（换脸/换眉眼），不重新生成整张——否则五官比例会变
- 表情数量按剧本实际需要：`python tools/shotlist.py` 会从台词里统计出精确清单（当前事件 01 只需要 5 个）

不同景别靠裁切：

| 景别 | 裁法 |
|---|---|
| 全景 | 整张 + 场景层 |
| 中景 | 裁到人物腰部以上 |
| 近景 | 裁到胸部以上，配合 `over` 层压低对比 |
| 特写 | 裁到肩部以上，加 `grade` 压暗 |

### 2.6 AI 生图提示词模板

给 `providers/image_jimeng.py`（豆包 Seedream）用的结构。**注意：现有实现只走文生图，没有参考图参数**——所以风格锚定必须靠"提示词常量 + 先生成一张风格样板图"来锁，或者升级到支持参考图的模型（可灵 Image 3.0 / Seedream 4.0 都支持图生图，能显著提升一致性）。

```
[景别] + [地点与时段] + [在场物件] + [光线与色温] + [风格锚点] + [画幅约束]

例（会议室内景 · far 层）：
  广角内景，现代写字楼三号会议室，空房间无人物，
  长条会议桌、投影幕布、百叶窗、几把转椅、墙上的季度目标板；
  冷白顶灯与斜射百叶光，色温 5000K，低饱和冷灰蓝调；
  扁平厚涂插画质感，硬边光影，轻微胶片颗粒，非写实皮肤；
  16:9 横构图，四周留出可裁切余量，画面边缘不放关键信息
```

风格锚点串（**每个角色/每个场景都复用同一串，这是唯一的一致性保障**）：

```
STYLE = "扁平厚涂插画质感，硬边光影，低饱和冷灰蓝色调，轻微胶片颗粒，非写实皮肤，企业职场题材"
```

**为什么推荐"扁平厚涂"而不是"日式赛璐璐"或"写实"**：厚涂的笔触和不精确的边缘本身就是风格，AI 的形体小偏差会读成"笔触"而不是"错误"；写实则会把每个偏差都暴露成穿帮。职场题材也需要"成年人感"，厚涂比动漫画风更合适。

## 3. 镜头语言

### 3.1 八种句型

一个"镜头"完全由四个数描述：`zoom`（推拉）、`focus`（缩放锚点）、`pan`（相机位移）、`dur`（时长）。八种句型就是这些数的八种组合：

| move | 何时用 | 数值模板 |
|---|---|---|
| `in` | 注意力收拢、进入情绪、说话人开始陈述 | zoom `[1.08, 1.15]`，pan ≈ 0 |
| `out` | 抽离、收束、留白、一段结束 | zoom `[1.15, 1.08]`，pan ≈ 0 |
| `pan_l` / `pan_r` | 扫视环境、暗示在场他人 | zoom `[1.14, 1.15]`，pan.x ±0.05 |
| `tilt_u` | 权威感、抬头看 | pan.y 从 +0.01 到 −0.01 |
| `tilt_d` | 压迫感、低头看 | 反向 |
| `hold` | **什么都不发生时用它**（见下方铁律） | zoom 变化 ≤ 0.003，`loop: true` |
| `push_shake` | 冲击、坏消息落地、负荷顶不住 | zoom `[1.10, 1.20]` + `shake: 2.4` |

数值全部写在 `data/shots.json` 里，`tools/shotlist.py` 会校验"标签和数值是否自洽"——标 `pan_r` 但数值在左移会被直接拦下来。

### 3.2 两条硬约束（校验器强制）

**① 过扫约束**：`|pan| × 最大图层深度 ≤ (zoom − 1) / 2`

因为缩放和位移共用同一个变换，可用余量就是 `(zoom−1)/2`。zoom 1.14 时最多平移 7% 屏宽。想平移更多就得把 zoom 提上去。不满足这条，画面边缘会露出来。

**② zoom ≥ 1.02**

zoom = 1 会让引擎做枢轴换算时除零；小于 1 会缩出边缘。

### 3.3 铁律：禁止全静止

**画面完全静止超过约 2 秒，玩家会判断"卡住了"。** 这是静态帧方案唯一真正的失败模式，也是它和"PPT"的唯一区别。

所以：**任何"什么都不发生"的时刻，必须用 `hold` 镜头——极微幅的持续呼吸（缩放 1.060 ↔ 1.063，8 秒一个来回）。**

这个幅度小到玩家说不出画面在动，但能感觉到"这个画面是活的"。成本为零，效果是整个方案能否成立的关键。所有 `hold` 镜头在镜头表里都设了 `loop: true`，校验器会强制这一点。

### 3.4 每场景最少三个机位

| 机位 | 作用 | 配置 |
|---|---|---|
| 定场（`entry`） | 交代空间，一段的开头 | `in` 或 `pan`，三层 |
| 反打左 / 右（`reverse`） | 对话的主要承载 | `in`，far + mid + `over`（肩） |
| 静物特写 | 承载信息（见 §6.3） | 单层，`hold` 或缓推 |

**反打由引擎自动切**：`ShotDirector.play_reverse(side)` 按说话人所在侧切机位。场景没配 `reverse` 时**保持当前镜头不动**——乱切镜头比不切更难看，旁白更不该切。这条规则写进了代码，不是约定。

## 4. 引擎动效的边界

这条分界决定"哪些事你不该去做"。判断标准是：**需要"物理正确"的运动，引擎做不了，AI 也做不好。**

| 动效 | 谁做 | 说明 |
|---|---|---|
| 推 / 拉 / 摇 / 横移 | **引擎** | `scale` + `pivot_offset`，见 §3 |
| 视差（分层差速） | **引擎** | pan × depth |
| 切镜 / 淡入 / 闪白 | **引擎** | 三行代码的事 |
| 全局压暗 / 色调 | **引擎** | 一个 ColorRect 叠加层 |
| 震动 | **引擎** | 每帧随机偏移 |
| 打字机 / 选项浮入 / 数值飘字 | **引擎** | UI 层 |
| 角色呼吸、轻微侧倾 | **引擎** | 立绘做 ±1% 的位移，成本为零 |
| 口型 | **AI（可灵）** | 只有这一项必须 AI |
| 微表情、头发衣物飘动 | **AI** | 极少量，仅供视频层用 |
| **走路、开门、递东西、翻页** | **谁都不做** | 引擎做不了，AI 可用率 25%，所以——**剧本里不要写需要这种动作的台词** |

最后一行是这份规格里唯一约束**编剧**的条款。它不是技术限制的妥协，而是"规则叙事"题材自带的红利：职场规则冲突的张力本来就来自**信息差和立场**，而不是肢体动作。

## 5. 视频层：准入规则与生产方式

### 5.1 三条硬标准（全中才允许用视频）

1. **只在立场反转或结局独白。** 立场反转 = 关系或态度发生不可逆扭转的那一刻；结局独白 = 五个结局的收尾段落。**不是"情绪激动"就用**——激动太常见了，用视频会失控。
2. **中近景，无大幅肢体动作。** 可灵数字人在中近景的表现最稳；一旦景别拉远，脸只剩几十像素，口型错误反而更明显。
3. **单条台词时长 ≥ 3 秒。** 太短的镜头不值得付转码代价和包体代价。

**反例（都不该用视频）**：普通对白、旁白、群像、环境空镜、任何需要走动的场面。

按 1.0 完整版约 97 分钟估算，这个准入规则自然会把视频量压在 **8% 左右（约 7.8 分钟）**，与预算分析一致。这个比例是**结果**，不是配额——不要为了凑 8% 去挑镜头。

### 5.2 判定流程

```
这句台词要拍吗？
  ├─ 是结局独白或立场反转？ ── 否 ──→ 静态帧
  ├─ 是中近景、没有大幅动作？ ─ 否 ──→ 静态帧（或改台词的拍法）
  ├─ 时长 ≥ 3 秒？ ──────── 否 ──→ 静态帧
  └─ 全中 ──→ 在剧本里标 "clip_candidate": true + "clip_dur": <秒>
```

标完之后**不要立刻做**。先跑 `python tools/shotlist.py`，让工具把视频量算出来，再决定做几条。

### 5.3 可灵数字人的拍摄法（这四条决定可用率）

数字人对口型的行业可用率约 **40%**，废片主因是口型不同步、牙齿/舌部崩坏。下面四条能把可用率往上推：

1. **同角色、同服装、同光、同景别**成组生产。这既是可灵的稳定性要求，也顺带保证了跨镜头一致。
2. **输入图用定妆立绘本身**，不要为视频单独重画一张脸——那会破坏 §1.3 的一致性优势。
3. **口型时长控制在 5 秒内**。越长越容易累积漂移。
4. **嘴部不要被遮挡**（手、杯子、麦克风都会让口型判定崩掉）。

### 5.4 编解码与降级

Godot 只吃 `.ogv`，所以：

```bash
ffmpeg -i raw.mp4 -c:v libtheora -q:v 8 -c:a libvorbis -q:a 5 -r 30 out.ogv
```

**质量不满意时的备选**：把 5 秒视频按 24fps 拆成 120 张 JPEG，用引擎逐帧播放。体积与视频相当（3~6MB），但画质无损、零编解码风险。只对少数几个关键镜头用这招。

**双形态降级机制（整条流水线的保险丝）**：镜头表里每个镜头都有 `clip` 字段。有值且文件存在 → 播视频；否则 → **自动退回该镜头的静态分层版**。

这意味着**视频层可以后期一条条补，补之前游戏完全可用**，开发和视频生产彻底解耦。视频播完还会自动切回该镜头的静态终帧，不会回到黑屏。

## 6. 规则叙事怎么落地

《隐形守护者》解决了"画面怎么做"，但没解决"题材怎么选"。《诡舍》给的答案是：**刻意避开真人演员更擅长的细腻情感表达**。落到《职级轮回》上，是四个具体转译。

### 6.1 把情绪外化成数值

不写"他失望了"，写"季衡态度 −8"。因为立绘表情只有 5 个，表现力上限很低；而数值是无限的，且玩家读数值比读脸更准。

现有 UI 已经具备条件：七维条 + NPC 好感条 + 结算飘字。**镜头和台词都应该主动为数值服务**——一句话说完，玩家应该想知道"这让我涨了还是跌了"。

### 6.2 给玩家一本可积累的《规则手册》

这是《诡舍》式"规则怪谈"的转译。核心是：**规则是唯一跨轮回保留的东西。**

- 每发现一条职场潜规则（"季衡只看材料不看加班时长""沈听澜要的是可验收的下一步"），解锁一张规则卡
- 回溯时数值清零、好感保留部分，**但规则卡全部保留**
- 玩家在第二、第三轮里变强，不是因为数值变高，而是因为**他知道规则了**

这一条同时解决了"回溯机制为什么好玩"——现在回溯只是重开，有了规则积累才叫"轮回"。

### 6.3 镜头转向"信息物"

规则叙事需要的是**线索**，不是**表演**。所以静物特写在这个题材里是核心机位，不是点缀：

| 信息物 | 承载什么 |
|---|---|
| 推到面前的周报模板 | 规则本身（三句话不够，要一页纸） |
| 白板上的季度/周次格 | **「轮回」的具象化**——12 个格子的物理形态 |
| 工位上的隔夜咖啡、便签 | 负荷与时间的流逝 |
| 屏幕右下角的时间 | 压迫感 |
| 体检报告 | 身心警报 |

**这类镜头正好落在 AI 最擅长的区间**：无人物（可用率约 50%，是最高的一档）、不需表演、画面对称。用最难被 AI 做坏的东西去承载最重要的信息——这是这条路线最漂亮的一处杠杆。

### 6.4 压力靠时间结构，不靠表情

12 周 × 多轮循环、晋升窗口的硬门槛、回溯的负荷代价（`mind_load` 递增）——这些压力**全部是结构性的**，不需要角色演出"焦虑"。

所以一个关键判断：**你现在这套策划书的核心机制，本来就是规则叙事的。** 唯一需要改的是表达方式——把重心从"季衡的一个眼神"移到"季衡的态度值降了 8 点"。

## 7. 生产流水线

六道工序，每道都有明确产出和验收。**任何一道的产出可以直接进下一道，不需要回头讨论。**

| # | 工序 | 谁做 | 工具 / 产出 | 验收 |
|---|---|---|---|---|
| 1 | **写剧本** | 你 | `data/story/*.json`（对话图） | `tools/shotlist.py` 零错误：引用完整、无断链、可达 |
| 2 | **出拍摄单** | 自动 | `tools/shotlist.py` → `docs/拍摄单.md` | 清单里的每个镜头都有 `label` |
| 3 | **出整图** | AI | 每个场景一张 2K 完整图 | 风格锚点串一致；四周留了 8% 余量 |
| 4 | **分层与补边** | 人工为主 | `assets/shot/...` | 层间透视一致；切缝外扩 8% |
| 5 | **引擎装配与调演出** | 你 | `data/shots.json` + 编辑器 | 无全静止画面；切镜频率合理（见 §8） |
| 6 | **视频层** | AI + FFmpeg | `assets/clip/*.ogv` | 只做准入通过的镜头；转码后实机播放不卡 |

第 2 道工序是这份规格带来的最大变化：**"要生成多少张图"不再靠拍脑袋，而是从剧本反推出来的确定数字。** 当前事件 01 跑出来的结果是 19 张被引用（含分层）、5 张立绘、0 条视频。

## 8. 验收标准

做完一段之后拿这五条自检：

1. **静止 5 秒会出戏** → 说明有镜头没设 `hold` 微呼吸。
2. **一屏同时有 3 个以上元素在动** → 太吵。同一时刻只让一个东西动：要么镜头动，要么立绘动，要么 UI 动。
3. **切镜频率**：一段 30 句台词，不超过 12 次切镜（平均 2.5 句一镜）。切太勤会晕，太稀会闷。
4. **缺图不黑屏。** 任何素材缺失时保留上一帧——这是零素材阶段能持续开发的前提，也是发行版防止白屏的保险。
5. **主色 ≤ 3 种。** 风格化的廉价感来自颜色太多，不来自画得糙。
